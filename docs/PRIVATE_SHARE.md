# 模组专用歌曲分享

本功能对应客户端 2.6.0、服务端插件 1.0.6。客户端通过 `v2.6.0` 标签触发 CI 发布；服务端插件仍仅在本地构建。

## 可见范围

- 点击歌曲分享后，客户端优先尝试通过 `cloudxmusic:share` 发送公开歌曲元数据。
- 插件仅向本服务器中完成专用分享握手的客户端连接转发，包括发送者自己；普通玩家和旧版客户端不接收此负载。
- 单人/LAN 主机、未安装配套插件、代理未转发新通道或 750ms 内未完成握手时，自动降级为公开聊天分享。
- 公开聊天正文携带 `#cxm:<source>:<id>…#` 短标记，本机和其他安装模组的客户端继续解析为可点击组件。
- 旧版客户端仍可能发送公开文字分享，新版保留接收兼容；要统一使用专用分享，需要更新发送者客户端。
- 未实现跨子服广播。客户端完成握手代表协议兼容，不是对客户端软件身份的防伪认证。

## 样式

旧版文字分享使用原消息组件的富文本片段，仅替换播放按钮并移除机器标记。颜色、继承字体、头衔、粗体和已有交互样式保持在对应片段上；动作栏和普通消息不改写。

专用分享不会经过服务器公开聊天插件。显示名优先使用客户端玩家列表中的富文本样式，否则显示游戏名；聊天插件专有前缀与排版不一定存在于玩家列表中，因此不承诺完全复现聊天格式。

## 降级策略

1. 进入服务器后发送 HELLO，并等待最多 750ms 的 WELCOME。
2. 已握手时发送专用 REQUEST，由服务端校验发送者并广播。
3. 单人/LAN 主机、握手超时、无插件或专用发送失败时，改用普通聊天发送 `ShareCodec.compose(...)` 的公开文本。
4. 本机通过 `ALLOW_CHAT` 把公开消息替换成带 `ClickEvent` 的组件；其他安装模组的客户端通过 `ALLOW_CHAT` / `MODIFY_GAME` 本地解析。替换失败或系统消息解析异常时必须保留原文，不能吞掉 MC / 服务器提示。

## 协议与线程

- 分享协议独立版本为 1，最大负载 1024 字节；原房间协议仍为 5。
- 新增 HELLO、WELCOME、REQUEST、BROADCAST、REJECTED 五类消息，严格验证 UTF-8、歌曲 ID、字段长度、时长及尾部字节。
- REQUEST 不携带发送者名字；发送者名称由服务端当前连接提供，客户端不能伪造 BROADCAST 请求。
- 网络入口沿用现有大小、令牌桶和待执行任务限制，分享另设每连接 1.5 秒冷却；重复握手不能重置冷却。
- 插件在 Global 调度上下文维护分享会话，投递使用目标玩家 Entity 调度器；退出、替换连接和关闭时清理资格，已关闭连接不能继续发送。
- 客户端握手和展示状态归客户端线程；断线清理状态，连接代次不符的接收任务丢弃。
- 不上传 Cookie、账号凭据、歌词、音频或授权音频链接。

## 安装与验证

1. 服务端停服后，将 `CloudXMusic-Server-1.0.6.jar` 放入 `plugins` 并替换旧插件，再正常启动。不要依赖 `/reload` 替换 Java 代码。
2. 退出游戏，将 `CloudXMusic-2.6.0.jar` 放入目标实例 `mods` 并替换旧 CloudXMusic JAR。
3. 使用两名新版模组玩家和一名未安装模组的玩家加入同一服务器。两名模组玩家应看到带链接的分享，普通玩家聊天中应没有该条内容。
4. 分别检查网易云与 QQ 分享、点击播放、未安装插件时的本地提示、重连后的重新握手，以及旧版文字分享的彩色头衔与自定义字体。

已建立离线编解码、转发范围、握手与冷却、断线清理及富文本样式回归验证；真实 Minecraft / Folia 联机与代理转发仍待验收。

2026-11-03 本地验证：客户端 443 项、协议 16 项、服务端 19 项测试全部通过，共 478 项，无失败、错误或跳过。客户端与服务端构建通过，已核对安装包内版本和分享通道类，客户端使用的协议库与本次协议构建产物 SHA-256 一致。

本地产物：`cloudxmusic-client/build/libs/CloudXMusic-2.6.0.jar` 与 `music-server/build/libs/CloudXMusic-Server-1.0.6.jar`。客户端发布结果以 GitHub Actions / Release 为准。

服务端与协议源码仍保留在本地；远端客户端通过更新后的 `libs/cloudxmusic-protocol.jar` 独立构建。
